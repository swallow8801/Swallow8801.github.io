## 들어가며

관제 카메라 한 대에는 사람도 지나가고 차량도 지나갑니다. "사람만 감지하는 모델"과 "차량만 감지하는 모델"을 따로 돌리면 같은 영상을 두 번 처리해야 하고, 두 결과를 화면에서 다시 합쳐야 합니다. 실무에서는 결국 하나의 모델이 여러 클래스를 동시에 잡아내는 멀티클래스 Object Detection으로 수렴하는 경우가 많습니다.

이 글은 YOLO 계열 모델로 사람·차량을 함께 실시간으로 탐지하는 시스템을 구성할 때 무엇을 먼저 정하고, 어디서 병목이 생기며, 어떻게 검증할지를 정리합니다.

---

## 클래스 설계가 먼저, 모델 크기는 그 다음

가장 먼저 정할 것은 모델 크기가 아니라 **무엇을 어떤 단위로 잡을지**입니다. "사람"과 "차량"만으로 충분한지, 아니면 "보행자/자전거 탑승자", "승용차/트럭/이륜차"처럼 더 세분화해야 하는지에 따라 데이터 라벨링 범위와 학습 난이도가 통째로 달라집니다.

```yaml
# data.yaml — 클래스는 운영에서 실제로 구분해야 하는 단위로
names:
  0: person
  1: bicycle_rider
  2: car
  3: truck
  4: motorcycle
```

클래스를 잘게 쪼갤수록 분류는 정교해지지만 클래스당 학습 데이터가 줄어 성능이 떨어지기 쉽습니다. 처음에는 "사람/차량" 정도의 큰 단위로 시작해 기준 성능을 잡고, 운영에서 더 세밀한 구분이 실제로 필요하다고 확인된 클래스만 나누는 순서가 안전합니다.

모델 크기는 이렇게 클래스 설계가 끝난 뒤에, 정확도와 처리 속도 사이에서 고릅니다. YOLO 계열은 같은 구조에서 nano부터 large까지 크기별 모델을 제공하므로, 작은 모델로 먼저 파이프라인을 통째로 돌려 본 뒤 정확도가 부족한 구간만 큰 모델로 올리는 편이 시행착오를 줄입니다.

---

## 실시간 처리의 병목은 모델 바깥에도 있다

"모델이 빠르다"와 "시스템이 실시간으로 돈다"는 다른 이야기입니다. 카메라가 여러 대로 늘어나면 병목은 종종 모델 추론이 아니라 그 앞뒤 단계에서 생깁니다.

| 단계 | 흔한 병목 | 완화 방법 |
| --- | --- | --- |
| 디코딩 | 다채널 영상 동시 디코딩 부하 | 하드웨어 가속 디코더 활용 |
| 추론 | GPU 큐 대기 | 여러 스트림 배치(batch)로 묶어 처리 |
| 후처리 | NMS·트래킹 연산 누적 | 프레임 스킵, 해상도 축소 |
| 전송 | 결과를 화면까지 보내는 지연 | 메시지 큐로 비동기 전달 |

특히 카메라 수가 늘어날수록 "프레임을 모두 처리할 것인가, 일부를 건너뛸 것인가"를 의도적으로 정해야 합니다. 사람 동선처럼 변화가 빠른 대상은 프레임을 건너뛰면 추적이 끊기고, 차량 진입 감지처럼 이벤트성 판단이면 일부 스킵해도 충분한 경우가 많습니다. 채널당 처리 가능한 FPS와 지연 시간은 실제 하드웨어에서 측정해 정합니다(`<측정값>`).

## 운영 환경에서는 클래스별로 따로 본다

학습 단계의 mAP 같은 종합 지표는 출발점일 뿐, 운영 검증은 **클래스별로 따로** 봐야 합니다. 사람 탐지는 잘 되는데 트럭만 자주 놓친다면 전체 지표는 괜찮아 보여도 실제로는 절반의 역할만 하는 셈입니다.

```python
# 클래스별 recall/precision을 분리해서 본다
for cls in ["person", "car", "truck", "motorcycle"]:
    print(cls, "recall:", recall_by_class[cls], "precision:", precision_by_class[cls])
```

운영에서 자주 부딪히는 두 가지도 미리 점검 목록에 넣어 둘 만합니다. 야간·역광처럼 조명이 급격히 변하는 시간대에 탐지율이 떨어지지 않는지, 그리고 비슷한 두 클래스(예: 자전거 탑승자 vs 보행자)를 혼동하는 빈도가 운영상 허용 범위인지입니다. 두 항목 모두 일반적인 벤치마크 점수로는 드러나지 않고, 실제 현장 영상을 따로 모아 확인해야 보입니다.

## 정리

다중 클래스 실시간 Object Detection 시스템은 (1) 모델 크기보다 클래스 설계를 먼저 정하고, (2) 실시간성의 병목이 모델 추론보다 디코딩·후처리·전송 단계에 있는 경우가 많다는 점을 염두에 두며, (3) 검증은 종합 지표가 아니라 클래스별로, 그리고 야간·혼동 케이스 같은 현장 조건까지 따로 확인하는 것이 핵심입니다. 처리 속도와 정확도 수치는 실제 운영 환경에서 측정한 값을 기준으로 삼으세요.
