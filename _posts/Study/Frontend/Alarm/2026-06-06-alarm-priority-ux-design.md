## 들어가며

관제 화면은 평온할 때보다 **알람이 한꺼번에 쏟아질 때** 진가가 드러납니다. 카메라 수십 대가 동시에 이상을 감지하면 화면은 순식간에 빨간 배지로 뒤덮이고, 운영자는 정작 가장 먼저 봐야 할 알람이 무엇인지 고르지 못한 채 화면만 바라보게 됩니다.

알람을 "발생하면 띄운다"는 단순한 규칙만으로는 부족합니다. 이 글은 알람에 우선순위를 매기고, 그 우선순위를 화면에서 어떻게 시각적으로 구분하며, 알람이 폭주하는 상황을 어떻게 다스릴지를 정리합니다.

---

## 알람에도 등급이 필요하다

모든 알람을 같은 무게로 다루면 결국 아무것도 중요해 보이지 않습니다. 화면을 설계하기 전에 알람을 최소 3~4단계로 나누는 기준부터 정합니다.

| 등급 | 의미 | 예시 | 기대 행동 |
| --- | --- | --- | --- |
| `critical` | 즉시 대응 필요 | 침입 감지, 화재 의심 | 즉시 확인·조치 |
| `warning` | 주의 깊게 살펴야 함 | 장시간 미확인 구역, 이상 패턴 | 우선순위 확인 |
| `info` | 참고용 | 모델 재시작, 설정 변경 | 필요 시 확인 |
| `system` | 운영 정보 | 카메라 재연결, 동기화 완료 | 로그 확인 수준 |

등급 기준은 도메인마다 다르므로, 실제 운영 데이터를 보고 "운영자가 실제로 먼저 반응한 알람이 무엇이었는지"를 역으로 추적해 등급 경계를 조정하는 편이 현장에 맞습니다(`<측정값>` — 운영 로그 기반으로 등급별 비율과 반응 시간을 측정).

---

## 시각적 강조는 색만으로 끝나지 않는다

`critical`을 빨강, `warning`을 노랑으로 칠하는 것은 시작일 뿐입니다. 색만으로 강조하면 화면에 빨강이 늘어날수록 오히려 무뎌지고, 색각 이상 사용자에게는 구분 자체가 어렵습니다. 등급이 올라갈수록 **강조 수단을 겹쳐서** 더합니다.

```css
/* 등급이 올라갈수록 강조 요소를 누적한다 */
.alarm--info     { border-left: 4px solid var(--gray); }
.alarm--warning  { border-left: 4px solid var(--yellow); font-weight: 600; }
.alarm--critical {
  border-left: 4px solid var(--red);
  font-weight: 700;
  animation: pulse 1.2s ease-in-out infinite;
}
```

```js
// 아이콘 + 텍스트 라벨을 항상 함께 둔다 (색만으로 구분하지 않음)
const badge = { critical: '🔴 긴급', warning: '🟡 주의', info: 'ℹ️ 정보' };
```

여기에 더해 **소리**도 강조 수단입니다. 다만 `critical` 알람마다 별도의 소리를 울리면 오히려 소음이 되므로, 등급별로 소리를 켤지·몇 초 간격으로 울릴지를 운영자가 조절할 수 있게 열어 두는 편이 좋습니다.

## 알람이 폭주할 때를 따로 설계한다

알람 우선순위 설계에서 가장 중요한 부분은 사실 "평소"가 아니라 **알람이 한꺼번에 쏟아지는 순간**입니다. 카메라 수십 대가 동시에 같은 원인(예: 네트워크 장애)으로 알람을 보내면, 화면에 똑같은 빨간 배지가 수십 개 나열되고 운영자는 "무엇이 새로 생긴 문제인지" 구분할 수 없습니다.

- **그룹핑**: 같은 원인·같은 시간대의 알람을 하나로 묶어 "OO 구역 카메라 12대 동시 알람"처럼 요약해 보여줍니다.
- **스로틀링**: 짧은 시간에 같은 알람이 반복되면 개수를 누적 표시하고, 화면에 새로 추가하는 빈도는 제한합니다.
- **신규 vs 누적 구분**: 방금 들어온 알람과 계속 쌓여 있던 알람을 시각적으로 분리해, "지금 봐야 할 새 알람"이 묻히지 않게 합니다.

```js
// 짧은 시간 내 동일 알람은 카운트로 누적
function upsertAlarm(list, incoming) {
  const dup = list.find(a => a.cameraId === incoming.cameraId && a.type === incoming.type);
  if (dup) { dup.count += 1; dup.lastSeen = incoming.time; return list; }
  return [...list, { ...incoming, count: 1 }];
}
```

이 세 가지를 적용하지 않으면, 알람이 가장 많이 필요한 순간에 화면이 가장 못 쓰게 되는 역설이 생깁니다.

---

## 정리

알람 우선순위 설계는 (1) 등급을 최소 3~4단계로 정의하고, (2) 색만이 아니라 아이콘·굵기·애니메이션·소리를 등급별로 누적해 강조하며, (3) 알람이 폭주하는 순간을 별도로 설계해 그룹핑·스로틀링으로 화면이 무너지지 않게 하는 것입니다. 등급 경계와 반응 시간 같은 수치는 실제 운영 로그를 보고 정하는 것이 가장 정확합니다.
