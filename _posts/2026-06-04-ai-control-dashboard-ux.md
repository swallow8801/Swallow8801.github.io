## 관제 UI의 핵심은 빠른 판단

관제 대시보드는 예쁜 화면보다 빠른 판단을 돕는 화면이어야 합니다. 사용자는 여러 카메라와 이벤트를 동시에 보면서 어떤 알람을 먼저 처리할지 결정합니다.

따라서 색상, 소리, 카드 크기, 정렬 방식은 모두 우선순위를 전달하는 방향으로 설계해야 합니다.

## 화면에 꼭 필요한 상태

| 상태 | 표시 이유 |
| --- | --- |
| 카메라 연결 상태 | 영상 장애와 실제 무이벤트를 구분 |
| 모델 동작 상태 | 추론 중단 여부 확인 |
| 알람 우선순위 | 긴급 이벤트를 먼저 처리 |
| 이벤트 처리 상태 | 미확인/확인/종료 흐름 관리 |
| threshold 설정 | 운영자가 민감도를 조정 |

## 다크 테마를 쓸 때

관제 화면은 장시간 보는 경우가 많아 다크 테마가 유리할 수 있습니다. 하지만 모든 것을 어둡게 만들면 알람 강조가 약해집니다.

배경은 낮은 대비로 두고, 위험 알람은 색과 위치, 모션을 함께 사용해 구분합니다. 단, 깜빡임은 피로도가 높으므로 정말 중요한 이벤트에만 제한적으로 사용해야 합니다.

## GIS 기반 UI

지도 기반 관제에서는 이벤트 위치와 카메라 방향이 중요합니다. 단순 마커보다 카메라 시야각, ROI, 알람 발생 지점을 함께 보여주면 현장 파악이 빨라집니다.

## 화면 우선순위 잡기

관제 화면에는 항상 더 많은 정보를 넣고 싶은 욕심이 생깁니다. 하지만 첫 화면은 사용자가 지금 무엇을 해야 하는지 알려줘야 합니다. 긴급 알람, 현재 장애 상태, 최근 이벤트가 우선이고, 상세 통계는 한 단계 뒤에 있어도 됩니다.

영상 그리드가 중심인 화면에서는 알람 목록이 너무 작아지지 않게 해야 합니다. 반대로 이벤트 대응이 중심인 화면에서는 영상보다 이벤트 상세와 처리 액션이 더 중요할 수 있습니다.

## 상태 색상 규칙

상태 색상은 프로젝트 초기에 규칙을 정해두는 것이 좋습니다. 빨강은 위험, 노랑은 주의, 파랑은 정보, 회색은 비활성처럼 일관된 의미를 가져야 합니다.

색상 규칙이 흔들리면 사용자는 매번 화면을 해석해야 합니다. 특히 다크 테마에서는 채도와 밝기를 조심해야 하고, 텍스트 대비도 함께 확인해야 합니다.

## 운영자 행동까지 설계하기

UI는 정보를 보여주는 것에서 끝나지 않습니다. 알람 확인, 담당자 배정, 메모 작성, 종료 처리 같은 행동이 자연스럽게 이어져야 합니다. 버튼 이름도 "확인"처럼 모호하기보다 "현장 확인 요청", "오탐 처리", "종료"처럼 상태 변화를 드러내는 편이 낫습니다.
