## 정답은 없지만 기준은 필요하다

불량 데이터는 항상 부족합니다. 특히 실제 라인에서 자주 발생하지 않는 결함은 몇 장만 모아도 시간이 오래 걸립니다. 그렇다고 데이터가 너무 적은 상태로 모델을 만들면 검증 결과가 운에 가까워집니다.

최소 수량은 모델 종류, 결함 난이도, 이미지 품질에 따라 달라지지만, 프로젝트를 시작할 때는 클래스별 목표 수량을 정해두는 편이 좋습니다.

## 데이터 수량을 볼 때의 기준

| 기준 | 설명 |
| --- | --- |
| 클래스 내 다양성 | 같은 결함이라도 위치, 크기, 조명 차이가 있는가 |
| 정상 다양성 | 정상 패턴이 충분히 넓게 포함되었는가 |
| 검증셋 독립성 | 학습 이미지와 비슷한 연속 프레임이 섞이지 않았는가 |
| 희귀 불량 처리 | 수량이 적은 클래스를 별도 정책으로 다루는가 |

## 희귀 불량 전략

샘플이 적은 불량은 처음부터 독립 클래스로 두기 어렵습니다. 비슷한 결함을 상위 클래스로 묶거나, anomaly detection 방식으로 정상 분포에서 벗어나는지 보는 접근도 가능합니다.

데이터 증강은 도움이 되지만 실제 결함 다양성을 완전히 대체하지는 못합니다. 증강은 모델을 튼튼하게 만드는 보조 수단으로 보고, 실제 샘플 확보 계획을 따로 가져가야 합니다.

## 검증셋이 더 중요할 때

데이터가 적을수록 검증셋 구성이 중요합니다. 같은 제품의 연속 촬영 이미지를 학습과 검증에 나누면 성능이 과대평가될 수 있습니다. 날짜, 라인, 작업 조건 기준으로 나누는 것이 더 현실적인 평가에 가깝습니다.

## 수량보다 다양성이 먼저인 경우

같은 불량 이미지 1,000장보다 서로 다른 조건의 200장이 더 가치 있을 때가 있습니다. 제조 데이터는 연속 촬영 이미지가 많아서 장수는 많아 보여도 실제 다양성은 낮을 수 있습니다. 같은 위치, 같은 조명, 같은 제품에서 나온 샘플은 모델 입장에서 거의 같은 문제입니다.

그래서 데이터 수량을 셀 때는 단순 이미지 장수와 유효 샘플 수를 구분하는 것이 좋습니다. 유효 샘플은 제품 타입, 결함 위치, 결함 크기, 조명 조건, 촬영 날짜가 얼마나 다른지까지 함께 봐야 합니다.

## 우선순위 기반 수집

모든 클래스를 같은 속도로 모으기는 어렵습니다. 운영 리스크가 큰 결함, 현재 모델이 자주 놓치는 결함, 작업자가 자주 헷갈리는 결함부터 우선 수집하는 편이 낫습니다.

| 우선순위 | 수집 대상 |
| --- | --- |
| 1순위 | 미탐 비용이 큰 치명 결함 |
| 2순위 | 오탐이 많이 발생하는 정상 변형 |
| 3순위 | 수량이 적어 평가가 불안정한 결함 |
| 4순위 | 향후 제품 변경으로 늘어날 가능성이 있는 패턴 |

## 데이터 확보 계획을 문서화하기

데이터가 부족하다는 말은 너무 넓습니다. 어떤 클래스가 몇 장 부족한지, 어떤 조건의 샘플이 없는지, 다음 라인 테스트에서 무엇을 수집할지까지 적어야 실행 가능한 계획이 됩니다.

이 문서는 모델 개발자뿐 아니라 현장 담당자와도 공유해야 합니다. 현장에서 어떤 불량을 일부러 만들 수 있는지, 실제 생산 중에만 관측되는지에 따라 일정과 실험 방식이 달라집니다.
