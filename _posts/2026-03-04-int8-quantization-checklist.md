## INT8은 공짜 최적화가 아니다

INT8 Quantization은 모델 메모리와 추론 속도를 줄이는 데 효과적입니다. 하지만 모든 모델에서 같은 효과가 나지는 않고, calibration 데이터가 부실하면 성능이 크게 떨어질 수 있습니다.

특히 불량 검출처럼 작은 신호를 보는 모델은 양자화 후 recall이 먼저 흔들릴 수 있습니다.

## 체크리스트

| 항목 | 확인 내용 |
| --- | --- |
| Calibration 데이터 | 운영 입력 분포를 대표하는가 |
| 클래스별 성능 | 희귀 불량 recall이 떨어지지 않는가 |
| 연산 지원 | ONNX/TensorRT 변환에서 지원되는 op인가 |
| Latency | 평균뿐 아니라 p95도 개선되는가 |
| 메모리 | 실제 GPU memory peak가 줄었는가 |

## 실험 순서

먼저 FP32 또는 FP16 기준 모델의 성능을 고정합니다. 그 다음 같은 테스트셋으로 INT8 결과를 비교합니다. 이때 threshold를 그대로 둘지, 양자화 모델에 맞춰 다시 튜닝할지도 분리해 기록해야 합니다.

속도는 단일 이미지 기준과 실제 배치 기준을 모두 봅니다. 실시간 시스템에서는 전처리와 후처리 시간이 모델 추론보다 더 큰 병목이 되는 경우도 있습니다.

## 배포 관점

모델 변환 파일만 만들어졌다고 끝이 아닙니다. 운영 장비의 GPU, 드라이버, TensorRT 버전에서 실제로 로딩되는지 확인해야 합니다. 배포 전에는 작은 smoke test를 만들어 입력 한 장으로 end-to-end 추론을 확인하는 것이 좋습니다.

## Calibration 데이터 구성

INT8 calibration은 모델이 실제 입력의 activation 범위를 추정하는 단계입니다. 이 데이터가 운영 분포를 대표하지 못하면 양자화 후 특정 상황에서 성능이 크게 떨어질 수 있습니다. 정상 이미지만 넣거나, 쉬운 샘플만 넣는 것은 위험합니다.

Calibration set에는 정상, 주요 불량, 희귀 불량, 조명 변화, 해상도 변화 샘플을 적절히 섞는 것이 좋습니다. 전체 데이터셋만큼 클 필요는 없지만, 운영에서 자주 만나는 입력 범위를 반영해야 합니다.

## 성능 하락을 해석하는 방법

양자화 후 성능이 떨어졌을 때는 모델이 작아져서 그렇다고만 보면 안 됩니다. 전처리 차이, 변환 과정의 op 대체, threshold 미조정, calibration 부족이 원인일 수 있습니다.

| 항목 | FP16 | INT8 |
| --- | --- | --- |
| 모델 파일 크기 | 기준값 | 비교값 |
| GPU memory peak | 기준값 | 비교값 |
| 평균 latency | 기준값 | 비교값 |
| p95 latency | 기준값 | 비교값 |
| 클래스별 recall | 기준값 | 비교값 |

## 롤백 가능한 배포

INT8 모델은 운영에서 성능과 속도를 모두 확인한 뒤 적용해야 합니다. 처음부터 기존 모델을 완전히 대체하기보다 FP16 모델과 INT8 모델을 함께 배포하고, 일부 카메라나 일부 라인에서만 먼저 비교하는 방식이 안전합니다.
