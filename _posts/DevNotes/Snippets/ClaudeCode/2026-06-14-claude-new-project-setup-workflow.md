새 저장소를 열고 Claude에게 "기능 만들어줘"부터 시키면 십중팔구 헤맨다. 프로젝트의 구조도, 명령어도, 컨벤션도 모르는 상태라 매번 같은 설명을 반복하게 되기 때문이다. 처음 30분을 세팅에 쓰면 그 뒤로는 설명을 줄일 수 있다. 이 글은 새 프로젝트에 Claude를 들일 때 내가 거치는 순서와, 반복 작업을 줄이는 활용 패턴을 정리한 메모다.

---

## 1단계 — CLAUDE.md부터 만든다

가장 먼저 하는 일은 프로젝트 루트에 `CLAUDE.md`를 두는 것이다. 이 파일은 세션이 시작될 때마다 자동으로 읽혀, 코드만 봐서는 알 수 없는 정보(빌드/테스트 명령, 아키텍처, 컨벤션)를 모델에 영속적으로 주입한다. 사람으로 치면 신규 입사자에게 건네는 온보딩 한 장짜리다.

직접 처음부터 쓰기보다 `/init`으로 초안을 만든 뒤 다듬는 쪽이 빠르다. `/init`은 저장소를 훑어 빌드 시스템·테스트 프레임워크·코드 패턴을 감지하고 시작용 `CLAUDE.md`를 생성한다.

```bash
# 프로젝트 루트에서
/init
```

생성된 초안에는 보통 군더더기가 많으니, 다음 골격만 남기고 줄인다.

- 한 문단짜리 프로젝트 요약 (무엇을 하는 서비스인가)
- 기술 스택
- 빌드 / 테스트 / 린트 명령
- 핵심 코딩 컨벤션과 "하지 말 것"

### 길이를 짧게 유지하는 이유

`CLAUDE.md`는 매 턴 컨텍스트를 소비한다. 길수록 정확도가 오르는 게 아니라 오히려 지시가 묻힌다. 한 화면(대략 60~80줄, 길어도 200줄 이내)에 들어오게 유지하는 편이 좋다. 세부 규칙이 많아지면 별도 문서로 빼고 `CLAUDE.md`에서는 링크만 건다.

---

## 2단계 — 컨벤션을 "명령"이 아니라 "규칙"으로 적는다

`CLAUDE.md`에 적는 문장은 권유가 아니라 규칙으로 쓴다. "가능하면 타입을 붙여 주세요"보다 "모든 공개 함수에 타입 힌트를 단다"가 훨씬 잘 지켜진다. 특히 효과가 컸던 항목들:

- 색상·폰트 같은 디자인 토큰은 한 곳(`_variables.scss` 등)에서만 관리하고 하드코딩 금지
- 데이터와 코드 분리 원칙 (예: 목록 데이터는 `_data/`로)
- 파일명·디렉터리 규칙을 예시와 함께 명시

예시를 한 줄이라도 같이 적어두면 추상적인 규칙보다 재현율이 높다.

---

## 3단계 — Explore → Plan → Implement → Commit

세팅이 끝나면 작업을 시킬 때의 흐름도 정해 둔다. 바로 구현으로 직행하지 않고, 먼저 관련 파일을 읽게 하고(Explore), 계획을 세우게 하고(Plan), 그다음 구현(Implement), 마지막에 커밋(Commit)하는 순서다. 큰 변경일수록 "먼저 계획만 보여줘"라고 한 번 끊어주는 것이 수정 비용을 크게 줄인다.

```text
1) "이 기능과 관련된 파일을 찾아서 읽고 요약해줘"   # Explore
2) "수정 계획을 단계별로 제안해줘. 아직 코드는 쓰지 마"  # Plan
3) (계획 확인 후) "그대로 구현해줘"                  # Implement
4) "변경사항을 커밋 메시지와 함께 정리해줘"           # Commit
```

---

## 4단계 — 반복 작업은 스킬·명령으로 굳힌다

같은 종류의 요청을 세 번 이상 하고 있다면, 그건 자동화 신호다. 자주 하는 절차(예: 정해진 규격으로 글 초안 만들기, 릴리스 노트 정리)는 스킬이나 커스텀 명령으로 굳혀두면 매번 설명할 필요가 없다. 최근 `/init`은 단순 스캔을 넘어 "어떤 반복 작업을 스킬로 만들지", "어떤 동작을 훅으로 막을지"까지 물어보는 방향으로 발전했으니, 초기 세팅 단계에서 이 질문들에 답해두면 좋다.

---

## 정리

순서를 요약하면: `CLAUDE.md`를 `/init`으로 만들고 → 짧게 다듬어 규칙을 명시하고 → Explore·Plan·Implement·Commit 흐름을 습관화하고 → 반복 작업을 스킬로 굳힌다. 핵심은 "모델에게 매번 설명하던 것을 파일로 한 번만 적어두는 것"이다. 초기 비용은 30분 남짓이지만, 프로젝트가 길어질수록 돌려받는다.

> 확인 필요: 본인 환경의 실제 `/init` 동작 버전과 팀 컨벤션에 맞춰 명령·규칙 예시를 교체할 것.
