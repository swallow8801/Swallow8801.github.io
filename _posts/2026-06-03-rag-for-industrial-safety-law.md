## 왜 법령 판단에 RAG가 필요한가

LLM은 문장을 잘 만들지만, 최신 조항이나 세부 규칙을 항상 정확히 기억하지는 못합니다. 산업안전 법령처럼 근거가 중요한 도메인에서는 모델의 답변보다 어떤 조항을 보고 판단했는지가 더 중요합니다.

RAG는 법령 문서를 검색해 관련 조항을 가져오고, LLM이 그 근거 안에서 답하도록 제한하는 구조입니다.

## 문서 구조화

법령 문서는 조, 항, 호, 별표처럼 계층 구조가 있습니다. 단순히 일정 길이로 자르면 근거 단위가 깨질 수 있으므로, 가능한 한 조항 단위로 chunk를 나누는 것이 좋습니다.

| 데이터 | 저장 포인트 |
| --- | --- |
| 조항 원문 | 답변 근거로 그대로 표시 |
| 조항 번호 | 인용과 링크에 사용 |
| 시행일 | 버전 관리 |
| 상위 법령 | 관계 탐색 |
| 키워드 | 검색 보조 |

## Vector DB와 GraphDB

Vector DB는 의미 기반 검색에 적합합니다. 질문이 "추락 위험이 있는 작업"처럼 표현되어도 관련 조항을 찾을 수 있습니다.

GraphDB는 조항 사이의 관계를 표현할 때 유용합니다. 법령, 시행령, 시행규칙, 별표가 서로 연결되어 있다면 그래프 구조가 탐색에 도움이 됩니다.

## 답변 형식

판단 결과는 결론, 근거 조항, 판단 이유, 추가 확인 사항으로 나누는 것이 좋습니다. 특히 안전 도메인에서는 "위반 가능성이 있음"과 "확정 위반"을 구분해 표현해야 합니다.

## 질문을 구조화하기

산업안전 질의는 자연어 그대로 들어오지만, 내부에서는 구조화해서 다루는 편이 좋습니다. 작업 종류, 장소, 장비, 위험 요인, 보호구, 작업 높이 같은 요소를 추출하면 검색과 판단이 안정됩니다.

예를 들어 "고소 작업 중 안전대 미착용"이라는 질문은 작업 유형, 위험 조건, 보호구 조건으로 나눌 수 있습니다. 이렇게 나눠진 정보는 검색 쿼리 확장과 답변 근거 구성에 모두 도움이 됩니다.

## 근거 부족을 인정하는 답변

법령 판단 시스템은 모르는 것을 모른다고 말할 수 있어야 합니다. 검색된 조항이 부족하거나 질문 정보가 애매하면 확정적인 답을 피하고 추가 확인 사항을 제시해야 합니다.

| 상황 | 답변 정책 |
| --- | --- |
| 근거 조항 명확 | 판단과 조항 제시 |
| 근거 일부 부족 | 가능성 표현과 추가 정보 요청 |
| 검색 실패 | 판단 보류 |
| 질문 범위 모호 | 조건을 나눠 재질문 |

## 평가셋 만들기

RAG 시스템은 검색과 생성이 함께 움직이기 때문에 평가셋이 필요합니다. 질문, 기대 조항, 기대 답변 방향, 금지 답변을 함께 적어두면 모델이나 검색 설정을 바꿀 때 회귀 테스트를 할 수 있습니다.

특히 법령 도메인에서는 답변이 그럴듯한지보다 근거 조항이 맞는지가 먼저입니다. 검색 top-k에 정답 조항이 들어오지 않으면 LLM 프롬프트를 아무리 고쳐도 한계가 있습니다.
