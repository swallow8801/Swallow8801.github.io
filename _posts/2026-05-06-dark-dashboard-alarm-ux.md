## 다크 테마는 목적이 있어야 한다

관제 화면은 장시간 켜져 있는 경우가 많습니다. 다크 테마는 눈의 피로를 줄이고 영상 중심 화면에 잘 어울립니다. 하지만 모든 요소를 어둡게 만들면 중요한 알람이 묻힐 수 있습니다.

다크 테마의 핵심은 배경을 낮추고 이벤트를 선명하게 올리는 것입니다.

## 알람 우선순위 표현

| 우선순위 | 표현 방식 |
| --- | --- |
| 긴급 | 높은 채도, 상단 고정, 즉시 확인 버튼 |
| 주의 | 색상 강조와 배지 |
| 정보 | 낮은 대비의 로그 항목 |
| 종료 | 회색 처리와 시간 표시 |

## 색상만 믿지 않기

색상은 빠르게 상태를 전달하지만, 색상만으로 의미를 구분하면 접근성과 인지가 떨어질 수 있습니다. 아이콘, 위치, 굵기, 라벨을 함께 사용해야 합니다.

빨간색은 정말 위험한 상태에만 써야 합니다. 사소한 상태까지 모두 빨갛게 표시하면 사용자는 금방 무뎌집니다.

## 실시간 상태 표시

카메라 상태, 모델 상태, 이벤트 처리 상태는 서로 다릅니다. 영상은 정상인데 모델이 멈출 수도 있고, 모델은 정상인데 카메라 연결이 끊길 수도 있습니다. 화면에서는 이 상태들을 분리해 보여주는 것이 좋습니다.

## 정보 밀도와 피로도

관제 대시보드는 많은 정보를 보여줘야 하지만, 모든 정보를 같은 강도로 보여주면 사용자가 피로해집니다. 평상시에는 조용하고, 문제가 생겼을 때만 화면이 강하게 반응해야 합니다.

카메라 목록, 이벤트 목록, 지도, 상세 패널은 역할이 다릅니다. 이벤트 목록은 시간과 우선순위가 중요하고, 지도는 위치 관계가 중요하며, 상세 패널은 판단 근거와 처리 액션이 중요합니다.

## 알람 카드 구성

알람 카드는 작은 공간 안에서 많은 의미를 전달해야 합니다. 이벤트 유형, 카메라 이름, 위치, 발생 시간, confidence, 처리 상태가 기본으로 필요합니다. 이미지 썸네일이 있다면 사용자는 텍스트보다 빠르게 상황을 이해할 수 있습니다.

| 요소 | 목적 |
| --- | --- |
| 이벤트명 | 무엇이 발생했는지 표시 |
| 위치 | 어디에서 발생했는지 표시 |
| 시간 | 최신성과 지속 여부 확인 |
| 상태 | 미확인/확인/종료 구분 |
| 근거 | 모델 결과와 threshold 확인 |

## 관리자 설정 화면

알람 UX는 화면 표시만으로 끝나지 않습니다. 운영자가 threshold, ROI, 알림 수신자, 조용한 시간대를 조정할 수 있어야 합니다. 설정 화면은 너무 복잡하지 않게 만들되, 변경 이력은 반드시 남겨야 합니다.

누가 어떤 threshold를 바꿨는지 기록하지 않으면 나중에 알람 품질이 변했을 때 원인을 찾기 어렵습니다.
