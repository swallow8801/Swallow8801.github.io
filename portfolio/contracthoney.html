Overview

계약서를 읽는 시간을 줄이고, 놓치기 쉬운 위험을 드러내다

계꿀은 기업의 계약 검토를 돕는 AI 어시스턴트입니다. PDF 계약서를 조·항·호 단위로 나누고, 각 문장의 위법 가능성과 독소 조항 여부를 확률로 제시합니다. 위법으로 판단된 문장은 관련 법률을 예측하고 세부 항·호와 판단 근거를 연결하며, 긴 계약서는 조항별로 요약합니다. 분석 이력과 계약서 버전 비교까지 하나의 서비스에 묶어 단순한 분류 모델을 실제 업무 흐름으로 확장했습니다.

Problem

불리한 조항은 계약서 안에 자연스럽게 숨어 있습니다

계약서에는 법률을 직접 위반하는 조항뿐 아니라, 한쪽 당사자에게 해지 권한이나 비용 부담을 편중시키는 조항도 포함될 수 있습니다. 표현이 복잡하고 조항 간 맥락까지 살펴야 하므로 비전문가가 위험을 발견하기 어렵고, 전문가 검토에는 시간과 비용이 듭니다. 계꿀은 법률 자문을 대체하는 대신 검토가 필요한 문장을 먼저 좁혀주는 사전 점검 도구를 목표로 설계했습니다.

위법 조항 법률이나 강행 규정을 위반할 가능성이 있는 조항
독소 조항 계약 당사자 한쪽에 과도하게 불리한 영향을 주는 조항
Solution

분석 결과를 판단 가능한 정보로 바꾸는 네 가지 기능

01
위법·독소 조항 식별

문장마다 위법 및 독소 가능성을 확률로 표시해 검토 우선순위를 빠르게 정할 수 있습니다.

02
관련 법률과 판단 근거

위반 가능성이 있는 법률 조항을 예측하고, 세부 항·호와 해당 판단의 설명을 함께 제공합니다.

03
조항별 계약서 요약

긴 계약서의 핵심 의무와 조건을 조 단위로 요약해 전체 내용을 빠르게 파악하도록 돕습니다.

04
분석 이력과 버전 비교

계약서별 분석 결과를 저장하고, 새 버전에서 변경된 조항과 위험도 차이를 비교합니다.

Architecture

웹 서비스와 AI 추론을 분리한 3-Tier 구조

사용자 화면은 Next.js, 비즈니스 로직과 AI 추론 API는 FastAPI로 분리했습니다. 계약 정보와 분석 결과는 Azure Database for MySQL에, 원본 PDF와 표준계약서는 Azure Storage에 저장했습니다. 각 애플리케이션은 Docker 컨테이너로 구성해 Azure에 배포했으며, 웹 서버가 Hugging Face 모델을 로드한 AI 서버와 REST API로 통신하도록 설계했습니다.

Service Flow

업로드부터 분석 이력과 버전 비교까지

사용자가 PDF를 업로드하면 텍스트를 추출해 조·항·호 단위로 분리하고, AI 서버가 위법·독소 식별과 법률 예측, 설명, 요약을 순차 수행합니다. 결과는 계약서 버전과 함께 저장되어 이후 분석 로그와 변경 내용을 다시 확인할 수 있습니다. 계정 영역에는 이메일 인증, 비밀번호 해싱, JWT 기반 4시간 인증 토큰과 입력값 검증을 적용했습니다.

AI Pipeline

하나의 거대 모델 대신 작업별 모델을 연결했습니다

PDF에서 추출한 계약 문장 8,260건을 정규식으로 조·항·호 구조에 맞게 전처리했습니다. 식별 모델은 데이터를 Train·Validation·Test 7:2:1로 나누어 비교했고, 각 작업에서 성능과 자원 효율을 함께 고려해 모델을 선정했습니다. 분류 결과만 보여주지 않고 법률 예측과 설명, 요약을 후속 단계로 연결한 것이 핵심입니다.

위법 식별
KoBERT + MLP

계약 문장의 위법 가능성을 분류합니다. 데이터 경계와 F1 균형을 검토해 임계값을 31.10%로 정했습니다.

독소 식별
KoELECTRA + MLP

불균형 데이터에서 Precision–Recall 기준을 적용해 판별 임계값을 58.67%로 선정했습니다.

위반 법률 예측
KLUE-BERT + Cosine Similarity

관련 법률의 조를 예측한 뒤 문장 임베딩 유사도로 가장 가까운 세부 항·호를 탐색합니다.

계약서 요약
EXAONE 3.5 · KoBART

두 한국어 생성 모델을 비교했습니다. EXAONE 학습에서 eval_accuracy 0.9333, perplexity 1.478을 기록했습니다.

“갑은 특정 조건에서 을에게 정보를 부당하게 제공하도록 요구할 수 있으며, 이로 인해 영업 비밀이나 개인정보를 침해할 수 있다.”
위법 확률 94.31% → 대규모유통업법 제15조 위반 가능성으로 예측
Outcome

모델 결과를 실제 계약 검토 화면으로 연결했습니다

사용자는 조항별 위법·독소 확률과 설명을 한 화면에서 확인하고, 관련 법령을 바로 찾아볼 수 있습니다. 조항별 요약과 이전 계약서 버전 비교를 더해 “위험 문장 탐지”에서 끝나지 않고 실제 검토 흐름을 이어가도록 구성했습니다. 다만 결과는 법률 자문이 아니라 검토 대상을 선별하는 보조 정보로 안내했습니다.

My Role

PM으로 흐름을 설계하고, 웹 기능을 직접 구현했습니다

7인 팀의 PM 및 웹 개발 담당으로 일정과 업무를 조율하고, AI 팀이 만든 추론 결과가 사용자의 계약 검토 과정으로 자연스럽게 이어지도록 화면과 API 요구사항을 정리했습니다. 계약서 분석 결과, 분석 이력과 버전 관리, 파일 업로드, 회원 및 마이페이지를 구현하고 프론트엔드·백엔드·AI API 연동을 담당했습니다.

  • 회원가입·이메일 인증·로그인·마이페이지 등 계정 기능 개발

Retrospective

정확도만큼 중요한 것은 결과를 설명하는 방식이었습니다

법률처럼 오판 비용이 큰 영역에서는 단일 예측값보다 확률, 관련 법령, 설명을 함께 보여주는 것이 중요했습니다. 또한 서로 다른 AI 모델의 입출력을 하나의 계약 구조로 정규화해야 웹과 데이터베이스가 단순해진다는 점을 배웠습니다. 다음 단계로는 DOCX·이미지 계약서와 OCR 지원, 분석 결과를 직접 수정하는 에디터, 계약 내용에 질의할 수 있는 근거 기반 챗봇을 추가할 계획입니다.
